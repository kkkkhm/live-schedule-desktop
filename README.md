# 直播排班工具

面向直播运营团队的本地桌面应用，集成灵活日期排班、班组管理、智能补班与加播、业绩排名、Excel 数据交换和渠道经营汇总。支持 Windows、Intel Mac 与 Apple Silicon Mac，日常使用无需安装 Node.js、Python 或启动本地服务器。

[下载最新版本](https://github.com/kkkkhm/live-schedule-desktop/releases/latest) · [版本记录](https://github.com/kkkkhm/live-schedule-desktop/releases) · [反馈问题](https://github.com/kkkkhm/live-schedule-desktop/issues)

## 下载与运行

在 [GitHub Releases](https://github.com/kkkkhm/live-schedule-desktop/releases/latest) 中选择与设备匹配的文件：

| 平台 | 文件名称 | 使用方式 |
| --- | --- | --- |
| Windows x64 | `LiveSchedule-Windows-<版本>-x64.exe` | 双击运行便携版 |
| macOS · Apple Silicon | `LiveSchedule-macOS-<版本>-arm64.zip` | 解压后打开 `.app` |
| macOS · Intel | `LiveSchedule-macOS-<版本>-x64.zip` | 解压后打开 `.app` |

macOS 版本目前未使用 Apple 开发者证书签名。首次打开若被系统阻止，可在“系统设置 → 隐私与安全性”中允许打开。

更新入口为 **帮助 → 检查更新**。应用会检查 GitHub Releases，并打开与当前系统匹配的下载地址；下载后由用户运行新版。更新前建议导出 JSON 备份。

## 功能概览

| 模块 | 核心功能 |
| --- | --- |
| 直播排班 | 选择任意 1–14 天区间，安排主播、副播、直播时间、加播和休假 |
| 历史记录 | 查看过去三个月及全部已保存的未来排班，按日期区间调出编辑 |
| 排班设置 | 自定义班次名称、直播间、班组、时间和每日最低目标 |
| 智能排班 | 按休假情况排入班组，优先补班，再分配加播时长 |
| 业绩排名 | 按班次录入业绩，分别生成主播榜与副播榜 |
| 经营汇总 | 从经营报表计算各渠道月度销售、退款与退款率 |
| 直播间与人员管理 | 新增、编辑、启用、停用及删除，保留历史名称快照 |
| 时长统计 | 汇总个人正常直播、加班和总时长，并检查排班冲突 |

编辑内容自动保存，同时提供“保存排班”按钮。已有排班按具体日期保留，重新打开相同日期即可继续编辑。

## 快速开始

1. 在 **人员管理** 中建立人员档案，设置主播、副播能力及用工类型。
2. 在 **直播间管理** 中添加直播间名称与账号。
3. 在 **排班设置** 中配置班次、班组、固定补班班组及每日最低目标。
4. 点击 **选择日期区间**，依次选择开始日期和结束日期，最多连续 14 天。
5. 在排班表底部选择每天的休假人员，填写休假备注。
6. 手动安排班次，或使用 **智能排班 → 生成区间排班**；修改后点击 **刷新排班提示** 重新评估当前内容。
7. 在 **业绩排名** 中录入班次业绩，或通过 **文件** 菜单导入、导出 Excel。

Windows 的应用菜单位于窗口顶部，macOS 的菜单位于系统菜单栏。**文件** 提供数据导入导出，**视图** 提供页面缩放，**帮助** 提供更新检查和本文档。

## 排班与统计规则

### 班次、班组和智能排班

班次与常规班组采用一套全局配置，分别最多支持 12 个。班次可配置名称、默认直播间、起止时间、加班权限和加班优先级；班组可配置主播、副播及默认班次，均支持排序和启停。

智能排班先排入当天无休假冲突的常规班组。当班次数低于目标时，优先用固定补班班组补一个空缺；总直播时长仍不足时，再按允许加班的班次及其优先级分配加播。每日目标按所有直播间的直播时长合计计算。

每个常规班组每天最多自动安排一个完整班次，固定补班班组每天最多自动补一个班次。固定补班班组可选择所有已启用且具备对应角色能力的人员，不受正式或兼职类型限制。可用人员、班次或加播容量不足时，应用会提示人工处理。

默认配置如下，均可修改：

| 配置项 | 默认值 |
| --- | --- |
| 主号早班 | 08:00–12:30 |
| 主号中班 | 13:00–17:30 |
| 主号晚班 | 19:00–23:30 |
| 副直播间班次 | 13:30–18:00 |
| 每日最低班次数 / 最低总直播时长 | 4 班 / 18 小时 |
| 正常直播时长 | 每班 4.5 小时 |
| 默认自动加班 / 每班最大允许加班 | 1.5 小时 / 1.5 小时 |

### 出勤与加播

出勤时间由直播开始时间确定：

| 直播开始时间 | 对应出勤区间 |
| --- | --- |
| 早于 11:00 | 08:00–16:00 |
| 11:00–15:59 | 11:00–19:00 |
| 16:00 及以后 | 16:00–23:30 |

每班超出正常直播时长的部分计为加班。系统优先在正常直播结束后加播，出勤区间容量不足时尝试前加播；自动加播受单班加班上限和出勤边界约束。排班表及展示版 Excel 的直播时间、直播总时长包含加播。

直播排班不支持跨午夜。结束时间须晚于开始时间，直播与加播须位于对应出勤区间内。同一人员时间重叠、同班主播与副播相同、休假当天仍有排班等情况会显示警告。

**刷新排班提示** 根据当前内容重新评估，不会重新生成排班。**一键清空当前排班** 需二次确认，会清空当前区间的班次内容及对应业绩，保留休假人员和休假备注。

### 业绩排名

每个班次的业绩金额完整计入该班主播与副播各自的榜单。例如班次业绩为 10,000 元，主播累计业绩增加 10,000 元，副播累计业绩也增加 10,000 元。

金额以人民币元录入，支持两位小数。排名可查看当前区间、近 30 天、近三个月或全部记录；相同金额采用并列名次。

## Excel 导入与导出

排班和业绩使用独立的 `.xlsx` 模板。请通过应用生成模板，并遵循工作簿内的填写说明。

| 文件菜单操作 | 用途 | 可重新导入 |
| --- | --- | --- |
| 下载空白排班模板 | 按当前日期区间和启用班组生成横向填写表，纵向为班组、横向为日期 | 是 |
| 导出可编辑排班模板 | 在相同模板中预填已有排班，供外部修改 | 是 |
| 导出展示版排班表 | 按日期分组，展示账号、班次、主播与副播姓名、直播时间、出勤时间和直播时长 | 否 |
| 下载空白业绩模板 | 生成待录入业绩金额的模板 | 是 |
| 导出业绩表 | 导出已有班次及业绩，供外部修改 | 是 |

排班模板绑定生成时的班组、人员、班次及直播间配置。配置变更后应重新生成模板，避免修改系统字段或删除模板配置工作表。

导入前会显示新增、更新、跳过记录及校验信息。存在阻断错误时不会写入数据；确认预览后才应用变更。排班导入支持“只更新已填写字段”与“完全覆盖重复记录”两种模式。

**文件** 菜单还提供排班 CSV、时长统计 CSV 和 JSON 完整备份。CSV 使用 UTF-8 BOM 编码，方便在中文 Excel 中打开。

## 渠道经营汇总

在 **经营汇总** 页面选择源 `.xlsx` 文件和月份，点击 **计算并保存**。页面展示视频号、抖音、小红书及全渠道汇总，包含账号数量、销售、退款和退款率。

源工作簿需包含以下工作表：

- `323_支付退款分析（更新）`：支付与退款明细。
- `渠道业绩汇总表`：渠道账号名单。
- `店铺清单`：账号与归属映射。

| 字段 | 计算口径 |
| --- | --- |
| 月份 | 明细表 S 列；仅按月份筛选，不另外筛选年份 |
| 渠道 | 明细表 C 列 |
| 归属 | 明细表 Q 列；缺失或公式错误时按 F 列账号查询店铺清单 |
| 本月销售 | R 列合计；值缺失时使用 L 列正金额 |
| 本月退款 | V 列合计，保留负数；值缺失时使用 L 列负金额 |
| 退款率 | 本月退款 ÷ 本月销售；销售为零时为零 |

各渠道按“渠道 + 归属”汇总，使用账号名单展示结果，无交易账号保留为零。全渠道按“归属 + 账号”合并，归属相同但账号不同的记录分别保留。无法识别归属的明细可展开查看，并随结果一起导出。

如果源表包含公式，请先在 Excel 或兼容软件中完成计算并保存，以便读取公式结果缓存。月份 S 列必须具有可读取的数值。

结果按月份独立保存在本机。同月重新计算需确认覆盖，其他月份保留；可切换历史月份、删除记录或导出 Excel。经营汇总与班次业绩分别管理，计算不会修改源工作簿。

## 数据保存与迁移

业务数据保存在当前设备的应用本地存储中，日常排班、Excel 处理和经营汇总可离线使用。检查更新和打开在线帮助需要网络连接。

通过 **文件 → 导出 JSON 备份** 保存人员、直播间、设置、排班、班次业绩和经营汇总记录；通过 **文件 → 导入 JSON 备份** 恢复。导入会覆盖当前数据，请先备份现有内容。

浏览器版与桌面版、不同设备的数据相互独立。更换设备或运行方式时，使用 JSON 备份迁移。旧版数据会在导入或加载时执行兼容升级。

## 开发与构建

开发环境使用 Node.js 22 与 npm。最终用户无需安装这些依赖。

```bash
# 安装项目依赖
npm ci

# 运行自动化测试
npm test

# 启动桌面开发版
npm start
```

在 Windows 上构建 x64 便携版：

```bash
npm run pack:win
```

在 macOS 上构建 Intel 与 Apple Silicon 两种架构：

```bash
npm run pack:mac
```

产物位于 `desktop-dist/`。macOS 打包脚本需在 macOS 环境运行。仓库内的 GitHub Actions 支持手动构建；推送 `desktop-v<版本号>` 标签后，会构建各平台安装包并自动创建 GitHub Release。

### 项目结构

```text
└── .github/workflows/  跨平台构建与发布流程
```
