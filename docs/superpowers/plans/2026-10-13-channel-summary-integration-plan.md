# 经营汇总功能实施计划

## 目标

把已确认的渠道月度汇总规则迁移为直播排班桌面应用内部的 JavaScript 功能，增加经营汇总页面、月度历史和 Excel 导出，并保持 Windows、macOS 共用同一实现。

## 实施步骤

1. 新增独立的 `channel-summary.js` 业务模块。
   - 识别经营报表所需工作表和字段。
   - 读取渠道账号清单与支付退款明细。
   - 使用分为单位的整数完成销售与退款汇总。
   - 生成视频号、抖音、小红书和全渠道汇总。
   - 返回未映射明细及具体原因。

2. 为计算模块增加自动化测试。
   - 构造包含完整名单、零金额账号、负数退款、跨渠道同账号和未映射记录的工作簿。
   - 验证逐行结果、各渠道合计、全渠道合并和错误处理。

3. 扩展应用状态迁移。
   - 新增版本化的 `channelSummaryRecords` 月度记录集合。
   - 兼容旧状态。
   - 增加同月覆盖和单月删除的纯逻辑测试。

4. 增加“经营汇总”界面。
   - 顶部导航入口。
   - 源文件、月份、开始计算操作。
   - 历史月份选择、重新计算、导出和删除操作。
   - 摘要卡片、四个渠道表格和未映射明细。

5. 接入应用事件和本地保存。
   - 用 ExcelJS 读取用户选择的 `.xlsx`。
   - 计算成功后保存月度记录。
   - 同月覆盖和删除使用二次确认。
   - 页面切换时渲染最近一条或当前选择记录。

6. 增加经营汇总 Excel 导出。
   - 生成“月度汇总”工作表。
   - 存在未映射记录时增加“未映射明细”工作表。
   - 验证金额、百分比和中文字段。

7. 更新样式、帮助和桌面构建文件清单。
   - 保持现有应用视觉语言。
   - 确认新业务模块进入 Electron 安装包。

8. 完成验证。
   - 运行逻辑、Excel、菜单和桌面测试。
   - 使用合成工作簿完成端到端导入与导出测试。
   - 运行 Windows 打包前静态检查。
   - 若恢复真实经营报表，再与旧 Python 工具的已知结果对账。

## 完成标准

- 用户可以在应用内选择经营报表和月份并看到四个汇总区块。
- 同月重新计算会确认后覆盖，其他月份保留。
- 无交易账号保留为 0，未映射明细清晰可查。
- 导出的工作簿与页面结果一致。
- 不需要 Python，不修改源文件，不影响现有直播排班与业绩功能。
- 全部自动化测试通过。
