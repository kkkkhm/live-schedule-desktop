# 业绩录入与主播副播分榜设计

## 目标

在现有直播排班工具中新增“业绩排名”功能。功能以当前排班数据为基础，在不重复编辑人员和直播时间的前提下，为每个已排班班次录入业绩金额，并分别生成主播排名和副播排名。

## 导航与页面结构

新增“业绩排名”导航项，与“周排班、历史记录、直播间管理、人员管理、时长统计”并列。

业绩页面包含三个区域：

1. 统计范围工具栏。
2. 简化业绩录入表。
3. 主播业绩排名与副播业绩排名。

页面沿用当前选中的主排班数据。主号早班、中班、晚班以及副直播间班次都参与业绩录入与统计。

## 统计范围

提供以下快捷范围：

- 当前区间：使用页面顶部选择的 1–14 天日期区间。
- 近30天：包含今天在内向前连续 30 天。
- 近3个月：从今天向前推 3 个自然月，到今天为止。
- 全部：读取当前排班所属直播间保存的全部日期。

切换范围只影响业绩表和排名，不修改顶部周排班的日期区间。

## 简化业绩表

每个存在排班内容的班次占一行，显示：

- 日期
- 星期
- 班次
- 直播间名称
- 主播
- 副播
- 业绩金额
- 保存状态

表格不提供主播、副播、直播时间、加班时间或直播间编辑功能。人员和直播间信息只读自排班；要更换人员，用户返回“周排班”修改。

业绩金额按人民币元保存，允许 0，最多两位小数，不允许负数或超过两位小数。未填写与填写 0 必须区分：未填写不参与排名数据，0 作为已录入业绩参与班次数统计。

金额修改后自动保存，并显示已保存状态。每个班次同时保存最后修改时间。

## 数据模型与归属

业绩数据直接保存在对应日期、对应班次记录中：

```text
performanceAmount: number | null
performanceUpdatedAt: ISO datetime | ""
```

一笔班次业绩完整计入该班主播，也完整计入该班副播。例如业绩为 10000 元，主播累计增加 10000 元，副播累计也增加 10000 元。由于两个角色使用独立排行榜，不在同一榜单内形成重复竞争。

排名在渲染时根据当前排班中的 `hostId` 与 `coHostId` 动态计算。周排班更换人员后，班次业绩保留在原日期和班次，并自动归属给更换后的人员。人员名称优先读取当前人员库，找不到时使用排班中的历史姓名快照。

兼职人员与正式员工使用相同规则，只要出现在主播或副播位置，就进入对应角色排行榜。

## 排名规则

主播榜与副播榜分别显示：

- 名次
- 姓名
- 累计业绩
- 已录入业绩的班次数
- 平均每班业绩

榜单按累计业绩从高到低排序；累计业绩相同时使用并列名次，下一名采用竞赛排名，例如 `1、2、2、4`。同金额人员的显示顺序按姓名排序，保证结果稳定。

未填写业绩的班次不参与累计、班次数和平均值。填写 0 的班次参与班次数，累计金额增加 0。

## 清空、历史与备份

“一键清空当前排班”删除班次记录时，会一并删除附着在班次上的业绩。二次确认文字必须明确提示业绩也会被清除，而休假人员与休假备注仍然保留。

业绩数据自动包含在现有 JSON 备份和导入中，不新增单独备份文件。现有旧数据没有业绩字段时按未填写处理，不需要提高数据版本或进行破坏性迁移。

历史记录页面暂不增加业绩列；业绩历史通过“业绩排名”页面的快捷范围查看。现有排班 Excel/CSV 和时长统计保持原样，本期不增加业绩导出，避免扩大范围。

## 错误处理

- 负数、非数字或超过两位小数时不保存，并在当前输入框附近显示错误。
- 班次缺少主播或副播时仍可显示，但业绩只计入已存在的角色；页面显示人员缺失提示。
- 当前范围没有已排班班次时，显示空状态，不生成空排名行。
- 本地存储失败时沿用现有保存失败提示，已输入值保留在页面供用户处理。

## 验证

- 相同班次业绩完整计入主播榜与副播榜。
- 主播、副播严格分榜；同一人员在不同角色出现时分别累计。
- 未填写与 0 的统计口径正确。
- 金额支持两位小数，拒绝负数、非数字和三位以上小数。
- 当前区间、近30天、近3个月和全部范围边界正确。
- 同金额采用 `1、2、2、4` 并列排名。
- 周排班换人后，业绩自动归属新人员。
- 一键清空排班同时清除班次业绩，但保留休假人员与休假备注。
- 旧 JSON 数据、现有排班、历史、时长统计、CSV 与 Excel 导出继续正常。
