# 排班表与业绩表 Excel 导入导出设计

## 目标

为直播排班桌面工具增加基于固定 Excel 模板的排班与业绩导入导出能力。用户可以导出当前数据或空白模板，在 Excel 中填写或修改后重新导入。导入前必须预览变更并完成校验，避免覆盖无关数据或因名称错误生成重复人员。

排班同时增加系统计算的出勤时间。出勤时间由直播时间自动确定，用户不单独填写；直播时间必须完整落在对应出勤区间内。

现有 JSON 全量备份继续保留，用于完整迁移和恢复；Excel 功能用于日常业务录入和交换。

## 功能入口

桌面端“文件”菜单提供：

- 导入排班表
- 导出排班表
- 下载空白排班模板
- 导入业绩表
- 导出业绩表
- 下载空白业绩模板
- 导入 JSON 备份
- 导出 JSON 备份
- 导出时长统计 CSV

排班和业绩的导入流程统一为：

1. 选择 `.xlsx` 文件。
2. 检查工作簿和字段结构。
3. 解析、匹配并校验数据。
4. 显示导入预览。
5. 用户选择默认更新或完全覆盖。
6. 用户确认后一次性写入。
7. 自动保存并刷新排班、历史记录、统计和排名。

## Excel 模板

### 排班模板

工作簿包含三个工作表：

- `填写说明`：字段解释、时间格式、导入规则和示例。
- `排班数据`：实际导入和导出的记录。
- `可选项`：当前系统中的直播间、班次和人员，用于 Excel 数据验证下拉列表。

`排班数据`包含以下列：

1. 日期
2. 直播间名称
3. 直播间账号
4. 班次
5. 主播
6. 副播
7. 开始时间
8. 结束时间
9. 加班开始
10. 加班结束
11. 备注
12. 休假人员
13. 休假备注
14. 系统记录标识

休假人员允许多人，使用中文顿号 `、` 分隔。`系统记录标识`为隐藏列，导出已有数据时写入；空白模板中可以为空。
同一日期、同一直播间的多条班次记录应填写相同的休假人员和休假备注；若同一文件内出现不一致，导入将其视为阻断性错误。

### 业绩模板

工作簿包含：

- `填写说明`
- `业绩数据`
- `可选项`

`业绩数据`包含以下列：

1. 日期
2. 直播间名称
3. 直播间账号
4. 班次
5. 主播
6. 副播
7. 业绩金额
8. 系统记录标识

业绩金额单位为人民币元，必须大于或等于零，最多保留两位小数。主播和副播字段用于核对当前排班，不用于改变排班人员。

### 模板行为

- 导出的现有排班或业绩文件可以直接修改后重新导入。
- 排班导出展示系统计算后的出勤时间，但排班导入模板不提供可编辑的出勤时间字段。
- 排班模板不包含业绩金额，导入排班不得改变已有业绩。
- 业绩模板只更新业绩金额，不修改人员、直播时间、加班或备注。
- Windows 和 macOS 使用完全相同的模板格式。
- 模板在工作簿中写入模板类型和模板版本元数据；程序只接受已声明兼容的版本。

## 记录匹配

导入时按以下顺序匹配记录：

1. 如果存在合法的系统记录标识，使用该标识定位原记录。
2. 否则使用“日期＋直播间账号＋班次”作为业务唯一键。

直播间账号必须匹配已有直播间；班次名称必须匹配已有班次；主播和副播姓名必须匹配已有人员。导入不自动创建人员、直播间或班次，以避免错别字产生重复数据。

若系统记录标识与业务唯一键指向不同记录，则视为阻断性错误，不允许导入。

## 校验规则

### 文件与格式校验

- 文件扩展名必须为 `.xlsx`。
- 必须存在目标数据工作表和全部必填列。
- 日期必须是有效日历日期。
- 时间必须使用有效的 24 小时格式。
- 业绩金额必须是有效的非负数，最多两位小数。

### 数据匹配校验

- 直播间账号必须存在。
- 班次必须存在。
- 非空的主播、副播和休假人员必须存在。
- 同一文件中不得出现重复的业务唯一键。
- 主播、副播名称与已匹配排班不一致时，业绩导入显示阻断性错误。

### 业务校验

- 主播和副播不能是同一人。
- 结束时间必须晚于开始时间；加班时间同样适用。
- 直播时间必须完整落在系统确定的出勤区间内。
- 检查同一人员的时间重叠。
- 检查休假人员当天仍被排班的冲突。

文件结构错误、数据无法匹配、重复记录或无效时间属于阻断性错误。人员时间重叠和休假冲突属于业务警告，用户明确确认后可以继续导入。

## 出勤时间规则

系统只使用以下三个出勤区间：

- 直播开始时间早于 `11:00`：出勤时间为 `08:00–16:00`。
- 直播开始时间在 `11:00–15:59`：出勤时间为 `11:00–19:00`。
- 直播开始时间在 `16:00` 及以后：出勤时间为 `16:00–23:30`。

直播开始时间不得早于对应出勤开始时间，直播结束时间不得晚于对应出勤结束时间。如果直播时间无法完整落在系统选定的出勤区间内，则该记录无效并禁止保存、自动排班或导入。

出勤时间是派生值，不作为独立状态保存。修改直播时间后，页面显示和 Excel 导出都重新计算出勤时间。Excel 导入不得单独设置或覆盖出勤时间。

## 更新策略

默认使用“只更新已填写字段”模式：

- Excel 单元格有值时更新对应字段。
- Excel 单元格为空时保留系统原值。
- 找不到已有记录时新增。
- 内容完全相同时跳过。

预览中提供“完全覆盖重复记录”选项。启用后，重复记录中的空白可清空对应排班字段。以下数据始终保持独立：

- 排班导入不改变业绩金额。
- 业绩导入不改变排班内容。
- 休假信息只由排班模板中的休假字段更新。

日期、直播间账号和班次是记录身份字段，任何更新模式下都不能为空。完全覆盖模式允许清空主播、副播、普通与加班时间、备注、休假人员和休假备注；它仍不得通过修改隐藏标识把一条记录移动到另一个日期、直播间或班次。

导入必须采用事务式处理：先在内存副本中应用所有变更和校验，全部通过后再替换当前状态并保存。任一阻断性错误都会取消整次导入，原数据保持不变。

## 导入预览

导入预览对话框显示：

- 文件名和目标类型。
- 总行数。
- 新增、更新、跳过的数量。
- 阻断性错误列表。
- 业务警告列表。
- 更新模式选择。

存在阻断性错误时禁用“确认导入”。只有业务警告时允许用户明确确认后继续。

导入成功后显示摘要，并立即：

- 刷新当前排班表。
- 同步历史记录与排班总览。
- 重新计算时长统计和主播、副播业绩排名。
- 将更新后的状态自动保存到本地。

## 程序结构

实现划分为三个职责明确的模块：

1. Excel 模板模块：生成空白模板、导出当前区间排班、导出业绩数据和可选项。
2. Excel 解析与校验模块：读取工作簿、标准化日期时间和金额、匹配系统数据、计算并校验出勤区间，再生成预览结果。
3. 导入执行模块：在状态副本上按选定策略新增或更新，完成最终校验后提交状态。

桌面原生菜单只发送受限命令给渲染进程。文件选择仍通过隐藏的文件输入控件完成，Excel 读写复用项目现有的 ExcelJS 能力。业务逻辑和 DOM 展示分离，解析与合并函数保持可独立测试。

## 错误处理

- 无法读取或损坏的工作簿：显示明确错误，不修改数据。
- 模板版本不兼容：提示重新下载最新模板。
- 工作表或字段缺失：列出缺失项目。
- 匹配失败：显示行号、字段和值。
- 导入执行异常：回滚整次导入并保留原数据。
- 保存失败：提示用户导出 JSON 备份，不宣称导入成功。

## 测试与验收

自动化测试至少覆盖：

- 排班模板导出后原样导回不会产生变更。
- 修改排班模板后正确新增和更新记录。
- 业绩模板修改金额后正确更新主播和副播排名。
- 默认模式下空白单元格不清空已有值。
- 完全覆盖模式可以清空允许清空的排班字段。
- 排班导入不改变业绩，业绩导入不改变排班。
- 不存在的人员、直播间和班次会阻止导入。
- 重复记录、无效日期、无效时间和无效金额会阻止导入。
- 三种直播开始时段均能得到正确的出勤区间。
- 直播开始或结束时间超出对应出勤区间时，保存、自动排班和导入均会被阻止。
- 修改直播时间后，页面和 Excel 导出的出勤时间会同步更新。
- 时间重叠和休假冲突会产生可确认的警告。
- 导入失败时原状态不变。
- Windows 和 macOS 生成的模板结构一致。

人工验收包括：从应用导出两个模板，在 Excel 中修改后重新导入，检查预览、自动保存、历史记录、排班总览、时长统计和业绩排名均正确刷新。

## 非目标

本次不支持任意第三方 Excel 格式自动识别，不在导入时自动创建人员、直播间或班次，也不提供云端多人协作或在线同步。
