# 经营汇总功能嵌入设计

## 目标

把同项目对话“查看报表并规划自动化计算”中已经完成的渠道月度汇总工具嵌入直播排班桌面应用。用户在应用内选择经营报表 Excel 和月份后即可完成计算、查看四个渠道区块、保存月度历史并导出结果，不再单独启动 Python 工具。

本次工作只合并渠道月度汇总能力，不改变直播排班、排班导入、业绩排名和现有历史记录的业务口径。

## 功能入口

应用顶部增加“经营汇总”导航项，与“直播排班”“历史记录”“业绩排名”等一级功能并列。

经营汇总页面包含：

1. 源 Excel 文件选择。
2. 月份选择，范围为 1 至 12。
3. “开始计算”按钮。
4. 已保存月份选择。
5. “导出 Excel”“重新计算”“删除本月记录”操作。
6. 计算摘要和四个渠道汇总区块。
7. 无法映射明细的警告及可展开列表。

## 技术方案

采用应用内部 JavaScript 计算模块，将现有 Python 工具的稳定业务规则等价迁移到 Electron 应用中。模块使用应用已经内置的 ExcelJS 读取和导出工作簿，不启动 Python 进程，也不在安装包中增加 Python 运行环境。

这样 Windows 和 macOS 共用同一套实现，沿用现有文件选择、下载、应用菜单和自动更新机制。

旧 Python 工具及其输出保持不变，作为迁移期间的对照实现和验收基准。

## 源文件识别

计算模块从用户选择的经营报表中读取现有业务工作表：

- 店铺或账号清单，用于取得各渠道的完整归属和账号名单。
- 支付退款明细，用于取得渠道、归属、月份、销售金额和退款金额。

工作表名称和字段位置优先按现有报表结构识别。读取前检查必需工作表和字段；缺失时停止计算，并明确指出缺少的工作表或字段，不生成部分结果。

源文件只读，应用不得覆盖或修改用户选择的经营报表。

## 计算口径

计算规则与现有 Python 工具保持一致：

1. 月份只筛选支付退款明细的 S 列，不使用年份或 N 列日期。
2. 视频号、抖音和小红书分别按 `渠道 + 归属` 汇总。
3. 每个渠道使用清单中的完整账号名单，无交易账号仍输出，金额为 0。
4. 本月销售汇总支付金额，保留两位小数。
5. 本月退款保持负数，保留两位小数。
6. 退款率为 `本月退款 ÷ 本月销售`；销售为 0 时退款率为 0。
7. 不输出合计、总计等非账号行。
8. “全渠道汇总”按 `归属 + 账号` 合并前三个渠道；同一归属下的不同账号分别保留。
9. 全渠道退款率使用合并后的销售和退款重新计算。
10. 无法映射到归属的明细不计入汇总，必须记录原因并展示警告。

金额计算使用适合货币汇总的定点方式，避免 JavaScript 浮点累加造成小数尾差；界面和导出文件统一显示两位小数。

## 页面展示

计算完成后，页面顶部显示：

- 计算月份。
- 源文件名称。
- 计算时间。
- 无法映射明细数量。
- 视频号、抖音、小红书、全渠道汇总各自的账号数、销售合计和退款合计。

下方依次显示四个区块：

1. 视频号。
2. 抖音。
3. 小红书。
4. 全渠道汇总。

每个区块使用相同列：

`归属｜账号｜本月销售｜本月退款｜退款率`

默认保持现有工具的账号顺序。表格支持页面滚动，不在浏览器端重新排序，以保证界面、历史记录和 Excel 导出顺序一致。

无法映射明细默认折叠，只显示数量和警告。展开后显示足以定位问题的行号、渠道、账号、原始归属和原因，不复制无关列。

## 月度历史

每次成功计算后，应用把以下内容保存在本地状态中：

- 月份。
- 源文件名称，不保存完整源文件路径。
- 计算时间。
- 四个渠道区块的明细和合计。
- 无法映射明细及原因。
- 数据结构版本。

同一月份重新计算时先二次确认，确认后整体覆盖该月记录。其他月份不受影响。

用户可在经营汇总页面选择历史月份、重新导出或删除单个月份。删除需要二次确认，不删除源 Excel，也不影响直播排班和业绩数据。

本地状态迁移必须兼容没有经营汇总字段的旧版本应用；升级后默认得到空的月度记录集合。

## Excel 导出

“导出 Excel”使用当前选中的月度记录，不重新读取源文件。

输出工作簿包含一个“月度汇总”工作表。视频号、抖音、小红书和全渠道汇总依次纵向排列，每个区块使用以下表头：

`归属｜账号｜本月销售｜本月退款｜退款率`

格式保持原自动化工具的简洁表格风格：渠道标题、列标题、金额两位小数、退款率百分比、区块间留空行。无交易账号保留为 0。

如果存在无法映射明细，增加“未映射明细”工作表，列出界面中相同的定位字段和原因。没有未映射明细时不创建该工作表。

默认文件名为 `渠道月度汇总-<月份>月.xlsx`，通过应用现有保存流程交给用户选择位置。

## 错误处理

- 文件不是有效 `.xlsx`：停止并提示重新选择。
- 缺少必要工作表或字段：列出缺失项，不保存月度记录。
- 月份无效：阻止计算。
- 账号或归属无法映射：继续处理可识别记录，在结果中展示警告和明细。
- 导出失败：保留已保存的月度记录，提示重试，不重新计算。
- 同月覆盖或删除：必须二次确认。

错误信息使用业务字段名称，不向用户显示 JavaScript 堆栈。

## 模块边界

新增代码按职责拆分：

- 经营报表读取器：只负责把 Excel 转换为标准化输入记录。
- 渠道汇总计算器：只接受标准化记录并返回四个渠道区块和未映射明细，不依赖 DOM。
- 经营汇总存储：负责版本迁移、月份覆盖和删除。
- 经营汇总页面：负责文件选择、月份输入、预览、历史切换和提示。
- 经营汇总导出器：把已保存结果生成 Excel。

计算器必须保持纯函数形式，方便与 Python 工具进行相同输入下的自动对账。

## 验收与测试

使用旧工具已经验证过的经营报表进行对照测试：

1. 视频号账号数一致。
2. 抖音账号数一致。
3. 小红书账号数一致。
4. 每个账号的销售、退款和退款率一致。
5. 全渠道的账号集合和逐行金额一致。
6. 各渠道及全渠道销售、退款合计一致。
7. 零金额账号仍存在。
8. 无法映射明细数量和原因一致。
9. 同月覆盖只替换目标月份。
10. 删除只移除目标月份。
11. 应用旧状态升级后能正常打开经营汇总页面。
12. 导出工作簿无公式错误，金额和退款率格式正确。
13. Windows 桌面构建完成烟雾测试。
14. macOS 打包配置中不新增 Python 依赖，功能使用相同 JavaScript 实现。

只有新旧工具对同一真实源文件产生一致结果后，才视为迁移完成。

## 不在本次范围

- 不修改原经营报表。
- 不从互联网自动下载经营数据。
- 不把经营汇总金额自动写入直播班次业绩排名。
- 不改变现有 Python 工具。
- 不新增云同步或多人协作。
