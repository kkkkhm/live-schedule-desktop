# 桌面应用原生菜单设计

## 目标

为直播排班桌面应用增加符合 Windows 与 macOS 平台习惯的原生菜单栏。菜单提供文件导入导出、页面缩放、检查更新和在线帮助入口，同时复用现有业务逻辑，避免形成两套数据处理流程。

浏览器版不显示原生菜单。页面顶部原有导入导出按钮和“排班设置”中的应用更新区域移除，避免与桌面原生菜单重复；浏览器版继续保留排班、管理和统计功能。

## 菜单结构

### 文件

- 导入 JSON 备份
- 分隔线
- 导出 JSON 备份
- 导出排班 Excel
- 导出排班 CSV
- 导出时长统计 CSV
- 分隔线
- 退出

导入和导出项目向渲染页面发送受控命令，调用页面中现有的导入、导出函数。导入仍使用现有确认提示；导出仍沿用当前文件名、日期范围和直播间校验规则。

“退出”使用 Electron 标准退出角色；macOS 按系统规范将退出入口放入应用菜单。

### 视图

- 放大：Windows/Linux 使用 `Ctrl++`，macOS 使用 `Cmd++`
- 缩小：Windows/Linux 使用 `Ctrl+-`，macOS 使用 `Cmd+-`
- 恢复默认大小：Windows/Linux 使用 `Ctrl+0`，macOS 使用 `Cmd+0`

缩放按 10% 调整，最小 50%，最大 200%，默认 100%。缩放只改变页面显示比例，不改变排班数据、导出内容或窗口尺寸。

### 帮助

- 检查更新
- 帮助文档

“检查更新”调用现有 GitHub Release 更新检查。最新版和错误状态使用页面提示反馈；发现更新时弹出确认框，确认后打开对应下载地址或发布页。

“帮助文档”打开公开仓库 README：`https://github.com/kkkkhm/live-schedule-desktop#readme`。该地址在桌面主进程内固定定义，不接受渲染页面传入任意外部网址。

## 架构

新增独立桌面菜单模块，由 Electron 主进程创建和安装原生菜单。模块只处理菜单结构、平台差异、缩放和固定帮助地址。

需要复用页面功能的菜单项通过主进程向当前窗口发送白名单命令。预加载脚本只暴露订阅这些命令的最小接口，并提供取消订阅能力；不暴露通用 IPC、文件系统或任意网址打开能力。

渲染页面维护命令到现有函数的明确映射：

- `import-backup` → 打开现有 JSON 文件选择框
- `export-backup` → 导出现有 JSON 备份
- `export-schedule-xlsx` → 导出现有排班 Excel
- `export-schedule-csv` → 导出现有排班 CSV
- `export-stats-csv` → 导出现有时长统计 CSV
- `check-update` → 执行现有手动更新检查

未知命令被忽略。窗口关闭时不再向已经销毁的页面发送命令。

## 平台行为

- Windows：菜单显示在应用窗口左上方。
- macOS：菜单显示在系统屏幕顶部，并增加标准应用菜单和编辑菜单，以符合系统习惯。
- 浏览器版：不显示原生菜单，页面现有功能不变。

## 错误处理

- 菜单触发导出时继续使用现有页面校验和提示。
- 帮助页面无法打开时显示系统错误对话框，不影响应用运行。
- 更新检查失败时沿用现有联网失败提示。
- 缩放达到边界后保持在 50% 或 200%，不继续变化。

## 测试与验收

- 自动测试校验“文件 / 视图 / 帮助”菜单及所有要求的子菜单存在。
- 自动测试校验允许的页面命令白名单，未知命令不能传入渲染页面。
- 自动测试校验缩放步长、默认值和 50%～200% 边界。
- 自动测试校验帮助地址固定指向当前公开仓库 README。
- 自动测试校验预加载脚本未暴露 Node.js 文件系统或通用 IPC。
- Windows 桌面包冒烟测试确认菜单可见、页面正常加载，现有排班数据和导出功能不受影响。
- macOS 继续由 GitHub Actions 构建 Intel 与 Apple Silicon 两个未签名 ZIP。
