# 灵活日期区间与近三月总览 V4 设计

## 目标

将固定周一至周日的周表改为灵活日期区间排班。用户选择开始日期与结束日期后，表格自动生成 1 至 14 个日期列。全部排班按“直播间 + 具体日期”统一保存，因此任意日期区间看到的同一天始终是同一份数据。

同时在休假人员栏增加每天共用的休假备注，并将近三个月排班集中到可筛选、可更新的纵向总览。

## 日期区间工具栏

原“选择日期”控件改为：

- 开始日期
- 结束日期
- 上一区间
- 下一区间
- 回到本期

规则：

- 开始和结束日期均可自由选择，不要求周一或周日。
- 最短区间为 1 天，最长为 14 天，包含首尾日期。
- 结束日期早于开始日期时拒绝加载并显示错误。
- 超过 14 天时拒绝加载并提示缩短区间。
- 上一区间和下一区间按照当前区间天数整体平移。
- 回到本期恢复为“今天起连续 7 天”。
- 表头显示真实星期和日期，列数随区间自动增减。

## 日级数据模型

数据版本升级为 V4。唯一排班数据源为：

```text
schedules[roomKey]
  roomId
  roomNameSnapshot
  roomAccountSnapshot
  days[YYYY-MM-DD]
    morning
    overtimeMorning
    afternoon
    overtimeAfternoon
    evening
    overtimeEvening
    leavePeople
    leaveNote
    updatedAt
```

日期区间只是读取和编辑这些日记录的窗口，不保存第二份排班。因此：

- 两个区间包含相同日期时，显示同一日数据。
- 在任一区间修改排班后，其他区间和总览立即反映变化。
- 不存在区间重叠冲突。
- 删除人员或直播间后继续使用历史快照。

## V3 到 V4 迁移

升级前保存完整 V3 JSON 到独立浏览器备份键，迁移成功后才覆盖主存储。

- 将每个 V3 周表按周一日期和星期键换算为具体 ISO 日期。
- 将班次、人员快照、时间、备注和休假人员迁移到对应日记录。
- 新增空字符串`leaveNote`。
- 若同一直播间的多个 V3 周表意外落到同一天，优先保留更新时间较新的非空记录，并保留原 V3 备份。
- V1/V2 导入先经过已有迁移，再转换为 V4。
- 迁移失败时不得覆盖当前数据。

## 排班表与休假备注

排班行保持：早班、加班、中班、加班、晚班、加班、休假人员。

每个日期的休假单元格包含：

- 多选休假人员
- 一个当天共用的“休假备注”输入框

休假备注最长 100 字，自动保存，并参与历史读取、JSON 备份和 CSV 导出。休假冲突检查继续按休假人员与当天排班判断，不依赖备注内容。

## 历史记录与区间调取

历史页改为日期区间管理：

- 开始日期
- 结束日期
- 直播间筛选
- “打开此区间”按钮
- “更新近三月总览排班表”按钮

历史区间同样限制为连续 1 至 14 天。点击“打开此区间”后，跳转到周排班页并加载该直播间、开始日期和结束日期。因数据按天保存，过去和新增排班都无需复制即可随时调出并继续编辑。

原“复制到新日期”功能移除；灵活区间与日级唯一数据源已经覆盖其使用场景，避免复制产生重复数据。

## 近三月总览

点击“更新近三月总览排班表”后，重新读取当前数据，生成从今天向前 3 个月至今天的纵向列表。按钮只刷新视图，不覆盖、删除或复制排班。

总览支持直播间筛选，按日期倒序排列，字段为：

- 日期
- 直播间
- 班次
- 主播
- 副播
- 时间
- 正常时长
- 加班时长
- 休假人员
- 休假备注

有排班的班次各占一行。当天只有休假信息而没有班次时，也生成一行休假记录。

## 导入、导出与统计

- JSON 导入兼容 V1、V2、V3、V4。
- 排班 CSV 导出当前直播间和当前日期区间，并增加休假备注。
- 时长统计汇总当前直播间和当前日期区间。
- 正常时长、加班时长和总时长口径不变。
- 休假冲突、人员时间重叠和无效时间警告继续生效。

## 测试与验收

自动测试覆盖：

- V3→V4 具体日期迁移。
- 1 天、7 天、14 天和跨周区间。
- 无效反向区间与超过 14 天。
- 两个区间访问同一天时数据一致。
- 休假备注保留、导出与历史读取。
- 近三月范围、排序和休假独立行。
- 普通直播、加班、人员冲突和休假冲突统计。

浏览器验收覆盖：

- 开始与结束日期控件。
- 日期列自动增减。
- 两个直播间的 7 天示例正确映射到周一至周日。
- 休假备注可编辑并自动保存。
- 历史区间可直接打开编辑。
- 更新近三月总览后能看到最新数据。
- 页面无控制台错误。
