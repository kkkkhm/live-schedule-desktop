# 历史总览包含未来排班设计

## 目标

历史记录总览不仅展示过去三个月内的排班，还要展示所有已经保存且包含实际内容的未来排班。用户提前排好的班不能因为日期晚于今天而在历史总览中消失。

## 展示范围

- 过去记录：从今天向前保留三个月（含阈值当天）。
- 今天：只要存在排班或休假内容就展示。
- 未来记录：所有已保存的非空日期均展示，不设置未来截止日期。
- 更早记录：早于过去三个月阈值的日期不进入总览。
- 空日期：没有人员、班次备注、加班或休假内容的日期不展示。

历史总览继续按日期从新到旧排列；因此较远的未来排班会排在前面，同一天不同直播间按既有直播间键排序。

## 数据与保存

不改变现有 V5 数据结构，也不迁移或复制排班。自动保存和“保存排班”仍直接更新原有 `schedules[roomKey].days[dateKey]` 数据。历史总览在渲染时读取这些已保存日期，并应用新的展示范围。

## 界面文案

- 历史页标题改为“历史记录与排班总览”。
- 说明改为“选择任意 1–14 天区间直接调出排班；总览显示过去三个月及所有已保存的未来排班。”
- “更新近三月总览排班表”改为“更新排班总览”。
- 刷新成功提示改为“排班总览已更新”。
- 空状态改为“过去三个月及未来暂无排班记录”。
- README 中同步说明历史总览的实际范围。

## 逻辑边界

历史筛选由 `historyRecords(state, todayValue)` 统一处理：日期只在早于三个月阈值时被排除，不再因为晚于今天而被排除。`hasDayContent` 继续作为是否为有效历史记录的判断依据。

## 测试

自动测试需要覆盖：

- 过去三个月内的非空记录会展示。
- 阈值当天的非空记录会展示。
- 早于阈值的记录不会展示。
- 今天的非空记录会展示。
- 所有未来非空记录会展示。
- 未来空记录不会展示。
- 返回顺序保持日期从新到旧。

现有桌面打包与启动测试继续执行，确保文案变化不会破坏桌面版本。
